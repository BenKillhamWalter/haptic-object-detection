# Prosthetic Hand Object Recognition System

This is the corrected code package for the capstone object-recognition workflow. It adapts the single-grasp tactile recognition idea to an underactuated prosthetic hand with six MLX90393 magnetic tactile sensors.

The code keeps the original 56-feature design:

- `t1` = first meaningful contact
- `t2` = final stable grasp / steady hold point
- classifier = Random Forest exported to Arduino C++ using `micromlgen`

## Hardware assumptions

| Component | Detail |
|---|---|
| Controller | OpenRB-150, SAMD21, 32KB SRAM, 256KB Flash |
| Motor | Dynamixel XM430-W350-R, ID 1, Protocol 2.0 |
| Motor positions | Open = 33 degrees, Close = 90 degrees |
| Multiplexer | TCA9548A at I2C address `0x70` |
| Strip 1 | TCA channel 0, Index sensors ID1/ID2 and Thumb sensors ID3/ID4 |
| Strip 2 | TCA channel 1, Middle sensors ID1/ID2 |
| Magnetic sensor library | arduino-MLX90393 by Theodore Yapo |
| Motor library | Dynamixel2Arduino by ROBOTIS |

Sensor addressing on each strip:

| Sensor ID | A1 pin | A0 pin | `begin()` call |
|---|---:|---:|---|
| ID1 | LOW | LOW | `begin(0, 0)` |
| ID2 | LOW | HIGH | `begin(0, 1)` |
| ID3 | HIGH | LOW | `begin(1, 0)` |
| ID4 | HIGH | HIGH | `begin(1, 1)` |

## Important fixes in this version

### 1. Data collection no longer needs Arduino Serial Monitor

The old workflow asked you to run `logger.py` and type labels in Arduino Serial Monitor. That is unreliable because both programs try to use the same serial port.

Now, `logger.py` does both jobs:

- sends the label to the OpenRB-150
- logs returned CSV rows into `grasp_data/`

### 2. Label validation was added

Accepted labels are exactly:

```text
cylinder_stiff
cylinder_soft
cube_stiff
cube_soft
```

Invalid labels are rejected before they can corrupt the dataset.

### 3. `t2` is now consistent between training and inference

Both data collection and inference now treat `t2` as the final stable hold sample, not the first instant where the encoder stops moving.

This better matches the steady-grasp concept used by the training feature extraction.

### 4. CSV sensor deltas are saved as floats

Magnetic sensor deltas are printed with three decimal places instead of being rounded to integers.

### 5. Random Forest evaluation is more honest

`train_and_export.py` now saves a cross-validated confusion matrix using `cross_val_predict`, instead of making the confusion matrix from predictions on the same data used for final fitting.

### 6. Class mapping is exported automatically

Training exports:

- `class_names.h`
- `model_config.h`
- `feature_names.txt`

`inference.ino` uses these generated files so the Arduino class-name order matches the trained model.

## Step 1 - Install libraries

### Arduino IDE

Install:

- `Dynamixel2Arduino` through Arduino Library Manager
- `arduino-MLX90393` manually as a ZIP library

### Python

From the `2_training` folder:

```bash
pip install pyserial pandas scikit-learn matplotlib micromlgen
```

---

## Step 2 - Collect training data

Flash:

```text
1_data_collection/data_collection.ino
```

to the OpenRB-150.

Then run:

```bash
cd 2_training
python logger.py
```

or, if needed:

```bash
python logger.py --port COM3
python logger.py --port /dev/ttyACM0
```

The logger will show this menu:

```text
1. cylinder_stiff
2. cylinder_soft
3. cube_stiff
4. cube_soft
```

For each grasp:

1. Place the object near the hand.
2. Type the label or number in `logger.py`.
3. Step back during the 2-second delay.
4. The hand will close, collect data, hold, release, then return to ready.
5. Repeat with varied object position and orientation.

Recommended dataset:

- minimum: 20 grasps per class
- better for demo reliability: 40 to 60 grasps per class

The CSV files are saved in:

```text
2_training/grasp_data/
```

## Step 3 - Tune contact detection if needed

In `data_collection.ino`, tune these constants:

| Parameter | Default | If contact is missed | If false triggers happen |
|---|---:|---|---|
| `CONTACT_THRESHOLD` | `40.0` | decrease | increase |
| `ENCODER_STILL_DEG` | `0.5` | increase slightly | decrease |
| `ENCODER_STILL_COUNT` | `5` | decrease | increase |
| `GRASP_TIMEOUT_MS` | `5000` | increase | usually leave |
| `HOLD_DURATION_MS` | `800` | increase for more settling | decrease for speed |

A good process is:

1. Run several empty grasps.
2. Look at the magnetic delta noise in the CSV.
3. Set `CONTACT_THRESHOLD` to about 3 to 5 times the noise floor.

## Step 4 - Train and export the model

From the `2_training` folder:

```bash
python train_and_export.py
```

Optional smaller model:

```bash
python train_and_export.py --trees 15 --depth 6
```

Optional larger model:

```bash
python train_and_export.py --trees 25 --depth 10
```

For OpenRB-150, stay conservative. Start with:

```bash
python train_and_export.py --trees 20 --depth 8
```

Training outputs:

```text
2_training/grasp_data/confusion_matrix_cv.png
3_inference/model.h
3_inference/model_config.h
3_inference/class_names.h
3_inference/feature_names.txt
3_inference/model_info.txt
```

The confusion matrix is cross-validated and is the better estimate of real performance.

## Step 5 - Flash inference

After training, open and flash:

```text
3_inference/inference.ino
```

Make sure these files are in the same folder:

```text
inference.ino
model.h
model_config.h
class_names.h
```

Open Serial Monitor at 115200 baud.

Commands:

```text
g = grasp and classify
r = recalibrate baseline
```

Expected output:

```text
# Prosthetic Hand - Inference Firmware
# Initialising hardware...
# Baseline done.
# Ready. Send 'g' to grasp/classify, or 'r' to recalibrate baseline.
# Grasp start.
# t1 captured at ... ms, sensor=...
# Stable grasp detected at ... ms. Holding before final t2 capture.
# t2 captured at final stable hold point, ... ms.
RESULT: cube_soft
```

## Feature vector order

Do not change this order unless you change it in all relevant files.

| Index | Description |
|---:|---|
| 0-17 | Delta X/Y/Z for all 6 sensors at `t1` |
| 18-23 | Per-sensor vector magnitude at `t1` |
| 24 | Motor encoder angle at `t1` |
| 25-42 | Delta X/Y/Z for all 6 sensors at `t2` |
| 43-48 | Per-sensor vector magnitude at `t2` |
| 49 | Motor encoder angle at `t2` |
| 50-55 | Magnitude change per sensor, `t2 - t1` |

## Troubleshooting

| Problem | Likely cause | Fix |
|---|---|---|
| `logger.py` cannot connect | Wrong serial port | Use `python logger.py --port COM3` or select from the menu |
| Motor not found | Wrong ID, baud, wiring, or power | Check Dynamixel Wizard, ID=1, baud=57600 |
| `t1` never detected | Threshold too high or sensors not near deformation zone | Lower `CONTACT_THRESHOLD`, check sensor placement |
| False `t1` before contact | Threshold too low or magnetic noise high | Increase `CONTACT_THRESHOLD`, recalibrate baseline |
| `t2` never detected | Encoder still condition too strict | Increase `ENCODER_STILL_DEG` or `GRASP_TIMEOUT_MS` |
| Many skipped grasps | Missing `t1` or `t2` flags | Review serial messages and tune thresholds |
| Good training accuracy, poor demo | Too little variation or overfitting | Collect more grasps with varied object pose/orientation |
| Model too large | Too many trees or depth too high | Reduce `--trees` and `--depth` |
| Inference does not compile | Generated files missing | Run `train_and_export.py` before flashing inference |

## Recommended capstone framing

This system is strongest as a single-grasp tactile object recognition pipeline. It is closest to the single-grasp Random Forest approach, adapted to magnetic tactile sensing on your custom underactuated prosthetic hand. It does not fully reproduce the short-exploratory-movement paper unless you later add a deliberate post-grasp movement stage.
